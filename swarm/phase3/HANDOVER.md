# Handover of the swarm work to the other engine

Generated by `python3 swarm/phase3/handover.py`. Do not edit by hand; `--check` fails when it is out of date.

## The three phases

- First phase (`swarm/ladder.py`): Drive one stage of the ladder: prepare its tasks before the agents start, score it after.
- Second phase (`swarm/phase2/stage.py`): Drive the second phase one stage at a time: prepare before the agents start, score after.
- Third phase (`swarm/phase3/CONTRACT.md`): The third phase scales that to 1,000 workers with three additions: a **queue** that workers draw tasks from, so every worker gets the same prompt and may do a batch of tasks; **adaptive waves**, where the size of the next wave follows what the last one measured; and **hardening**, so a thousand pieces of worker-written code can be run safely.

## Running the tests

From the root of the repository, with the standard library only:

    python3 -m unittest tests.test_swarm
    python3 -m unittest discover -s tests -p 'test_p3_*.py' -t .

Each test file can also be run alone, for example `python3 -m unittest tests.test_p3_handover`.

## Where each phase keeps its evidence

- First phase: `swarm/evidence/` and `swarm/state/` (benchmark results, resource metrics, task state).
- Second phase: `swarm/phase2/evidence/` (`stages.json`) and `swarm/phase2/RESULTS.md`, written by `stage.py report`.
- Third phase: private working files under `SWARM_HOME/p3` (default `~/.gaie-swarm/p3`), never in the repository. No evidence folder for it is defined here.

## The task store

Task coordination is private and file-backed, in a state directory outside Git. The protocol does not run agents. Its subcommands, as listed by `python3 -m engineering_os.orchestration --help`, are: `status`, `create`, `route`, `claim`, `renew`, `handover`, `submit`, `review`, `fail`, `recover`, `checkpoint`, `restore`. Every call takes `--state-dir DIR` first, for example `python3 -m engineering_os.orchestration --state-dir DIR status`. Leases fence coordinator writes only; actors are caller-supplied assertions.

## What the reviewer must decide

1. The order in which the three branches stack: `claude/swarm-100x100`, then `claude/swarm-phase-2`, then `claude/swarm-phase-3`.
2. The author never merges. The merge and the release belong to the reviewer.
3. `.claude/settings.json` sets a PreToolUse gate (matcher `*`) for every session started in this repository. Its command is `sh -c 'command -v swk-hook >/dev/null 2>&1 || exit 0; exec swk-hook'`. When the gate program is not installed that command exits 0, so every call is allowed: the session runs ungated. Install the gate before any worker starts.
