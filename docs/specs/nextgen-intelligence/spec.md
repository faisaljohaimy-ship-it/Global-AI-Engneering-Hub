## Scope and acceptance

1. Reasoning: classify task complexity, build hierarchical dependency plans under
   explicit budgets, compare evidenced architecture alternatives, flag uncertainty,
   and require source-bound deterministic verification and independent review
   before a decision can be accepted. Actual model invocation is separate.
2. Memory: private project-scoped persistent graph, deduplication, symbol and
   concept retrieval, architecture/decision/solution/failure/recovery records and
   checksum checkpoints shared by Codex and Claude Code. Keep all operational
   memory outside Git; never ingest customer records or secrets. Lexical retrieval
   must not be presented as embedding-based semantic search.
3. Factory: transform structured requirements into an ordered engineering artifact
   contract spanning selected database/API/frontend/backend/mobile/AI targets,
   tests, security, release and documentation. Gate advancement on actual artifact
   bytes and source/project-bound evidence; never label a plan a generated system.
4. Healing: compare diagnostic, regression, performance and dependency evidence;
   propose repairs and verify bounded artifact repairs in private disposable
   directories. Never execute untrusted candidate code or auto-deploy repairs.
   Artifact checks must not be represented as runtime regression verification.
5. Cinematic: independently inventory PR #16 original 200 names, preserve main's
   distinct 400-recipe catalogue, add bounded original remaining motions with
   actual runtime proof, and withdraw operational claims on source/proof drift.
   State viewport/browser coverage separately from real-device performance.
6. Economics: account for coordinator and workers, retries, cached input and
   verified outcomes; report feature/MVP/enterprise attribution and review,
   infrastructure, maintenance and rework. Token usage, price estimates, charged
   amounts and unavailable subscription allowance remain separate.
7. Integration: lazy-load engines through one offline Python CLI, add shared
   invocation instructions, test negative inputs and end-to-end synthetic flows,
   publish a reviewable independent branch/PR with source-bound evidence.

## Observable failure cases

Cycles, impossible budgets, wrong-project/source proofs, changed artifacts,
duplicate usage, incomplete coordinator data, malformed JSON, stale proof,
credential-shaped content and public memory directories must fail closed or
produce explicit blocked/unknown results. No record is operational merely
because its identifier appears in a manifest.
