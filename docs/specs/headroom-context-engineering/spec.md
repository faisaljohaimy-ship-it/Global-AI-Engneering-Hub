# Headroom context engineering

Owner P0, 2026-11-28: provide a concrete local Headroom SDK capability, then resume
the twenty-layer extension. Extend the existing modular Hub rather than replacing
its twelve implemented foundations, SDK contracts, thirteen skills or 430 motions.
Headroom becomes the fourteenth first-party instruction skill and one additional
reviewed catalog identity. Preserve other writers and concurrent recovery work.

## Scope

Use optional `headroom-ai==0.45.0` at upstream commit
`ce0460cfa8598dc939243dbc7aec4b2d35f4e44a` in a separately reviewed private venv.
Provide a standard-library launcher and isolated sibling SDK worker for local
tool JSON/log preparation, explicit code/policy passthrough, original retention,
SHA256 verification and retrieval. No proxy, wrapper, MCP registration, model call,
authentication change, instruction-file rewriting or production dependency.

## Acceptance

- **A1 — Compatibility/discovery:** the original 122 catalog rows and thirteen
  skills remain intact, one Headroom row records scoped approval after independent runtime review,
  and existing SDK/CLI/motion behavior remains compatible. Selected vendoring
  includes launcher and worker together; no runtime install is automatic.
- **A2 — Local execution:** `status`, `optimize --input --store --kind` and
  `retrieve --store --id [--query|--full]` expose real bounded outcomes. Code,
  policy, protected system/user envelopes and short inputs pass through. The
  actual SDK path uses verified agent-mode densification with system/user
  compression false and ML disabled; missing/failed SDK does not fabricate success.
- **A3 — Recovery:** retain original bytes and their full SHA256 in a private
  store outside Git before relying on optimized output. Retrieval verifies that
  digest; corrupt/missing/traversal/symlink/unsafe inputs fail closed. Full verified
  retrieval is mandatory before sensitive actions. SDK cache TTL is not a backup.
- **A4 — Isolation:** run the same reviewed interpreter with `-I`, task-local
  offline/telemetry/state controls and an explicitly reported network boundary.
  No global host/authentication configuration, provider call or paid service is
  changed. Unsupported isolation or dependency availability remains explicit.
- **A5 — Measurement honesty:** distinguish bytes, exact tokens, estimated tokens,
  unknown model-context usage and unknown billing. Preserve original passthrough
  and failure evidence. Report Codex tool-session execution separately from native
  Codex/Claude/MCP activation and actual authenticated model invocation.
- **A6 — Review:** independently review source, optional dependency closure,
  licenses/advisories and focused positive/negative tests, then require current-head
  Hub CI before any merged release. Product release gates remain independent.
