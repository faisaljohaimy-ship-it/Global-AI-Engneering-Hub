# Native Chromium engineering stack

Recovered from candidate branch `feat/chromium-motion-stack` at
`d7d28e41912305ef7c418035490f8ab7fbc51a8d`. Its three source files are retained in
Git history. Its 18 unpinned `latest` dependencies were never an approved runtime.
This implementation narrows installation to the already reviewed Apache-2.0
Playwright 1.63.0 and its integrity lockfile. Dependabot PR8 proposes 1.65.1;
metadata review alone does not justify an upgrade or blanket engine activation.

```sh
npm ci --prefix motion-library/chromium-stack --ignore-scripts --no-audit --no-fund
motion-library/chromium-stack/node_modules/.bin/playwright install chromium --only-shell
node --test tests/test_chromium_stack_options.mjs
node tests/test_chromium_stack_runtime.mjs
node motion-library/chromium-stack/smoke.mjs --frames 30 --frame-budget-ms 20 \
  --out /tmp/a-new-chromium-evidence-directory
```

The probe binds a fresh localhost port, blocks external page requests, and opens
new isolated browser contexts. No external network or CDP attachment, credentials or provider
calls. Actual checks cover Canvas pixels, CSS/WAAPI interpolation, GLSL shader
compilation/draw/readPixels across two uniform states, WASM execution, optional
OffscreenCanvas pixels, logical direction, mobile layout and reduced-motion static
alternatives. Screenshots and a source-hashed JSON receipt are optional exports.

WebGPU API/adapter, View Transitions and Scroll Timeline are reported separately as
availability only. They are not counted as rendered engines. WebGL may use a
software renderer; inspect the report. Three/React Three Fiber/GSAP/Motion/Remotion/
Theatre/Rive/Lottie/Puppeteer/Lighthouse/axe/MCP remain separate candidates and are
not installed by this stack.

The bounded benchmark records real RAF intervals and draw time, including the
configured budget result. A failed configured budget produces a failing CLI exit
status even when functional rendering assertions pass. It applies only to a tiny
local Canvas/transform workload.
It is not a production FPS/Web Vitals result, a cross-browser certification or proof
that all catalog motions meet a budget. Use a measured suitable workload before
making those claims. No code or movie is generated by an unavailable engine.
